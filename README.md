# 서비스 소개

<!--
  한두 문장으로: 누가, 무엇을, 어떻게 쓰는 서비스인지.
  3D 상권 + 가상 방문자 + 가게 실험으로 거제 옥포의 빈 점포 문제를 다룬다.
  서비스 이름은 아직 정하지 않았다. 정해지면 제목과 이 칸에 넣는다.
-->

동남권(부산·울산·경남)에서 상가 공실률이 가장 높은 **경남 거제 옥포 상권**을 3D 지도로 옮긴 웹 화면입니다.
빈 점포에 가게를 열려는 사람이 가게를 열기 전에
**"이 빈 자리에 이런 가게를 열면 손님이 올까?"**를
가상 손님(조선소 통근자·외국인 근로자·주민·주말 관광객)으로 먼저 실험해 볼 수 있게 만드는 것이 목표입니다.

> 가상 손님은 실제 사람이 아닌 계산용 인물입니다.
> 결과는 실제 매출 예측이 아니라 **조건끼리 비교하는 용도**입니다.

## 해결하려는 문제

<!-- 대상(누가) · 상황 · 불편 · 핵심 근거(수치+출처) 순서로 쓴다. 근거는 docs/ 조사 문서에서 가져온다. -->

**누가:** 거제 옥포의 빈 점포에 가게를 열려는 예비 창업자, 빈 점포를 채우려는 건물주와 거제시.

**상황: 옥포는 동남권에서 빈 상가가 가장 많은 상권입니다.**

| 항목 | 값 | 출처 |
|---|---:|---|
| 옥포 상가 공실률(건물 전체, 일반 상가) | **32.77%** | 한국부동산원 R-ONE 상업용부동산 임대동향조사, 2026년 3분기 |
| 옥포 큰 건물(중대형) 공실률 | **37.99%** | 같음 |
| 동남권 46개 상권 중 순위 | **1위** | 같음(`docs/dongnam-ranking.md`) |
| 2년 전 옥포 공실률 | 25.60% | 같음, 2024년 3분기 |
| 같은 거제시 고현 공실률 | 14.78% | 같음, 2026년 3분기 |
| 경남 평균 공실률 | 16.33% | 같음, 2026년 3분기 |

- 2년 새 25.6% → 32.8%로 올랐고, 경남 평균보다 **16.4%p** 높습니다.
  같은 거제시 고현은 14.8%라서, 공실은 거제 전체가 아니라 **옥포에 몰려 있습니다.**
- 보도가 짚은 원인은 같습니다. **조선소 실적은 살아났는데 옥포 상권은 살아나지 않았습니다.**
  소비 중심이 아주동 등으로 옮겨 갔고, 인구 구조가 외국인 근로자 중심으로 바뀌었습니다.
  (시사저널 2026-02-27, GIB 거제인터넷방송 2026-10-18, 뉴시스 2025-04-22. 링크는 `docs/okpo-evidence.md` 2절)

**불편:**

- **어디가 비었는지 알 수 없습니다.**
  옥포 빈 점포의 주소를 공개한 목록이나 기사는 찾지 못했습니다.
  기사는 "임대문의 딱지"처럼 모습만 전합니다(`docs/okpo-evidence.md` 4절).
- **열어 보기 전에는 손님이 올지 알 수 없습니다.**
  누가 언제 이 거리를 지나가는지(조선소 출퇴근, 외국인 근로자, 주말 관광객)를 가게 자리마다 따져 볼 도구가 없습니다.
- **빈 점포를 채우는 지원은 옥포가 아니라 고현에 들어갑니다.**
  - 고현은 중소벤처기업부 상권활성화 사업 80억 원(2025~2029)으로 빈 점포를 공용 공간(인큐베이팅랩)으로 바꾸고 있습니다(거제인터넷신문 2026-11-23).
  - 옥포는 도시재생 뉴딜(2026년 예산 70억 원)과 거리 전선 지중화(15억 원)가 있지만,
    **빈 점포를 직접 채우는 사업은 확인되지 않았습니다**(브릿지경제 2025-11-22).
  - 거제시 상권활성화 예산은 2026년 25억 원에서 2027년 21억 원으로 줄었습니다(새거제신문 2026-11-20).

## 핵심 기능

<!--
  시연 화면에서 실제로 보여 줄 수 있는 기능만 적는다.
  '만드는 중'인 기능은 화면에서 확인되면 '됨'으로 바꾼다. 확인 전에는 '됨'으로 적지 않는다.
  숫자는 화면이 쓰는 자동 생성 파일(web/data/*.js)과 같아야 한다. 자료를 다시 받으면 여기도 고친다.
-->

| 기능 | 상태 |
|---|---|
| 1. 옥포 상권 3D 지도 + 공실률 카드 | 됨 |
| 2. 층마다 가게 없는 상가 층 표시 | 됨 |
| 3. 가상 손님 하루 + 빈 층에 가게 열어 보기 | 됨 (손님 수·비율은 아직 가정 값) |
| 4. 인허가 폐업 기록으로 찾은 빈 점포 후보 | 만드는 중 |

- **기능 1. 옥포 상권 3D 지도 + 공실률 카드**
  - 건물 3,238채를 실제 모양·층수로 세웠습니다.
    국토교통부 GIS건물통합정보 2,922채가 기본이고, 거기 없는 건물을 OpenStreetMap 216채, Overture Maps 100채로 메웠습니다.
    층수를 확인한 건물은 2,358채입니다.
  - 도로·바다·녹지·지명과 R-ONE '거제옥포' 상권 경계 선을 같이 그립니다.
  - 건물을 누르면 지번·용도·사용승인일과 층별 정보가 나옵니다.
  - 요약 카드에 옥포 공실률(32.8%, 동남권 1위)과 2년 추이를 같은 거제 고현·경남 평균과 나란히 그립니다.
    숫자는 `tools/web_stats.py`가 R-ONE 원자료에서 직접 만듭니다.
- **기능 2. 층마다 가게 없는 상가 층 표시**
  - 건축물대장 층별개요(1,646개 지번)로 층마다 용도를 알아내고,
    소상공인 상가정보(2026년 9월, 1,714곳)에서 그 층에 영업 중인 가게가 있는지 대조합니다.
  - 결과: **R-ONE 상권 안 상가 층 1,273개 중 494개(면적 48.5%)에 등록된 가게가 없습니다.** 이 층을 3D 안에서 주황으로 칠합니다.
  - 이 값은 공실률과 같지 않습니다.
    상가정보에 잡히지 않는 사무실·창고·미등록 가게가 섞이기 때문입니다. 화면에도 이렇게 적었습니다.
  - 판정 규칙: 동이 여럿인 지번은 층을 섞지 않습니다. 업무시설은 뺍니다. 사무소·의원·학원처럼 상가정보에 잘 안 잡히는 쓰임은 '확인 불가'로 둡니다.
- **기능 3. 가상 손님 하루 + 빈 층에 가게 열어 보기**
  - 조선소 통근자·외국인 근로자·주민·주말 방문객이 05시부터 다음 날 02시까지 옥포를 오가며 가게를 고릅니다.
  - 건물 정보창에서 빈 층을 골라 업종·가격·자리를 정하면, 평일·주말을 5번씩 돌려 결과를 보여 줍니다.
    손님 수, 매출, 손님 구성, 시간대, 주변 가게에 주는 영향, 업종끼리 비교표가 나옵니다.
  - **약점:** 하루에 상권에 나오는 사람 수와 비율은 아직 가정 값입니다.
    근거 수치(조선소 종사자 27,118명, 거제 외국인 17,352명, 옥포 외식 가격 등)는 `docs/okpo-persona-sources.md`에 모았습니다.
    아직 화면 계산에는 넣지 않았습니다.
- **기능 4. 빈 점포 후보** (만드는 중)
  - 행정안전부 인허가(일반·휴게음식점)의 거제시 폐업 기록을 지금 영업 중인 가게와 대조해, 빈 점포일 가능성이 큰 자리를 뽑습니다.

## 만든 과정

<!--
  "어떻게 만들었나"를 단계별로 적는다. 단계마다 무엇을 했고, 어떤 스크립트·문서·PR에 남았는지 적는다.
  판단 기준이 바뀐 이유도 남긴다(심사·발표 때 "왜 옥포인가"에 답하려고).
-->

1. **대상지 고르기: 공실률이 가장 높은 상권을 숫자로 찾았습니다.** (PR #2·#4·#5·#9·#11)
   - 한국부동산원 R-ONE Open API로 부산·울산·경남 상권의 공실률을 9개 분기(2024년 3분기~2026년 3분기) 받았습니다(`tools/reb_fetch_busan.py`).
   - 기준은 **건물 전체(일반 상가) 공실률**로 정했습니다. 1층만 보면 3층 건물에서 2층이 비어도 놓치기 때문입니다.
   - 처음에는 부산 안에서만 골랐습니다(부산대학앞 → 남포동).
     동남권 전체로 넓히자 거제 옥포가 46개 상권 중 1위였습니다(32.8%). 그래서 옥포로 바꿨습니다(`docs/dongnam-ranking.md`).
2. **근거 모으기: 원문을 직접 열어 확인한 것만 씁니다.** (PR #1·#6·#7·#10·#14·#16)
   - 공실 원인 보도, 거제시 예산과 상권 사업, 조선소 종사자 수, 외국인 인구, 외식 가격을 원문(기사·통계표·엑셀·보도자료)으로 확인했습니다.
   - 검색 요약으로만 본 것은 '미확인'으로 따로 모았습니다(`docs/okpo-evidence.md`, `docs/okpo-persona-sources.md`).
   - 기사 숫자는 R-ONE 원자료와 맞춰 봤습니다. 예를 들어 기사의 '옥포동 중대형 35.3%'는 R-ONE 2025년 4분기 35.33%와 같았습니다.
3. **상권 경계 따기** (PR #14)
   - R-ONE 상권구획도 그림 한 장에서 '거제옥포' 경계선을 추적했습니다(`tools/rone_boundary_trace.py`). 약 0.66㎢입니다.
   - 상권 이름 글자가 선을 덮은 8화소는 직선으로 이었습니다. 그림에서 딴 근사치입니다.
4. **3D 지도 만들기** (PR #12·#15)
   - 국토부 건물, OSM 도로·바다·녹지, Overture 건물을 받아 범위만 잘랐습니다.
     `tools/map_build.py`가 이것을 하나로 합쳐 `web/data/okpo_map.js`를 만들고, 화면은 이 파일만 읽습니다.
5. **층별로 가게 없는 층 찾기** (PR #15)
   - 건축물대장 층별개요 API를 지번마다 불러(`tools/bldg_floors.py`) 상가정보와 층 단위로 대조했습니다(`tools/okpo_floors.py`).
6. **가상 손님 만들기** (PR #15·#16·#42·#46, 페르소나 v0.5.0, #64·#76·#80)
   - 손님 4부류의 출발지는 실제 자리에서 가져왔습니다. 집은 주거 건물, 입구는 조선소 쪽 큰길 끝과 OSM 버스 정류장입니다.
   - 가게는 상가정보의 실제 가게입니다(`tools/okpo_sim_data.py` → `web/sim.js`).
   - 지금은 가상 시민 24,336명을 1명씩 그대로 움직입니다(페르소나 v0.5.0, `tools/build_personas.py` → `web/data/okpo_personas.js`).
     옥포1동 동시 체류 인원·주민·일자리 같은 통계에 맞춰 뽑았고(보정 14개 항목 통과), 맞출 때 쓰지 않은 외부 통계 8개와도 비교했습니다(8개 통과).
     상인회 인터뷰를 반영해 조선소 직원 대부분은 사내식당에서 점심을 먹고, 외국인 근로자는 거리에 나와도 돈을 적게 씁니다.
   - 업종은 21개 세부 업종(백반·고깃집·호프·베트남 음식 등)으로 나눴습니다.
     한 사람이 쓰는 돈은 대표 메뉴 가격 × 한 사람이 시키는 양으로 계산합니다(예: 고깃집 = 삼겹살 200g × 1.1 + 소주 + 공깃밥).
     메뉴 가격은 거제시 개인서비스 가격동향(2026-11-26, 옥포1·2동 업소)과 옥포 업체 공개 가격에서 가져왔고, 못 찾은 것은 '가정'으로 표시합니다.
   - 재생 막대를 옮겨도 멈추지 않게 2시간마다 상태를 저장해 두고 그 자리부터 이어서 계산합니다.
     처음부터 다시 계산한 결과와 같은지 확인했습니다. 길 찾기는 가게·입구·정류장에서만 길 나무를 만들어(무방향 길이라 거꾸로 따라가면 됨) 첫 화면을 1초 안팎으로 줄였습니다.
7. **화면: 왼쪽 기록지 + 오른쪽 지도** (PR #43·#47·#50·#62·#74)
   - 화면 시안 세 개(조사 기록지·도로명판·이야기 순서)를 만들어 보고 '조사 기록지'를 골랐습니다.
     왼쪽에 구간 목록·요약·거리 기록·범례를 모으고, 오른쪽에 지도를 둡니다. 폰은 위가 지도, 아래가 기록지입니다.
   - 처음 칠한 편집 디자인(명조 제목·형광펜)은 "AI가 만든 화면 같다"는 지적을 받았습니다.
     그래서 국내 서비스 앱 문법으로 다시 칠했습니다: Pretendard 한 벌, 회색 띠로 영역 구분, 화면마다 꽉 찬 파랑 주 버튼 하나.
   - 화면 글은 뜻·시제·숫자가 맞는지 모두 다시 읽고 넣었습니다(예: '비어 가는 가게들' → '비어 있는 가게들').
8. **지도 고도화: 바닥·건물·녹지를 나눠 그렸습니다** (PR #51~#91)
   - 바닥(`web/ground.js`): OSM 길·주차장·토지 이용·해안선 위에 그린 표현입니다. 아스팔트·보도블록 질감, 바다 깊이 색·물거품, 토지 이용 색, 밤에 은은한 포장 빛을 넣었습니다.
     큰길 양쪽 인도와 15cm 연석(교차로 모서리는 곡선), 양방향 큰길 중앙선은 있다고 보고 그렸고, 실제 모양은 확인하지 않았습니다. 차선은 OSM에 차로 수가 있는 길에만 그렸습니다.
     횡단보도는 공공데이터포털 '전국횡단보도표준데이터'(거제시, 기준일 2026-07-20)로 다시 그렸습니다. 지도 안 214건 중 좌표가 한 건짜리이고 차도 위에 있는 38곳만 그렸고(점자블록·보도턱 낮춤도 자료대로), 같은 좌표에 여러 건이 묶인 145건 등은 자리를 알 수 없어 그리지 않았습니다(`data/processed/okpo_crosswalks.csv`에 이유).
     어린이보호구역은 '전국어린이보호구역표준데이터'에 시설 위치 5곳과 도로 폭만 있고 지정 범위가 없어 바닥에 칠하지 않았습니다(`data/processed/okpo_school_zones.csv`). 신호등 표준데이터는 지도 안이 0건입니다.
     정지선·화살표·과속방지턱·맨홀·빗물받이는 자료가 없어 그리지 않습니다.
   - 건물(`web/app.js`·`web/floors.js`): 건물 종류별 창, 상가 1층 가게 앞면, 가게 없는 층의 주황 띠·주황 지붕.
     하루 빛도 넣었습니다. 재생 시각에 따라 해·하늘이 바뀌고, 밤엔 창 불이 켜지며 가게 없는 층은 꺼져 있습니다.
   - 녹지·정류장(`web/decor.js`): 공원·숲 안의 나무·관목(11월 말 색), OSM 버스 정류장 쉼터, 지도 밖 '한화오션 옥포조선소 방향' 이름표.
   - **공공 자료에 없는 물건은 그리지 않았습니다.** 한때 가로수·가로등·신호등·볼라드·도로명판·전봇대·벤치·놀이기구·주차된 차·현수막·물탱크를 분위기용으로 세웠지만,
     실제 위치 자료가 없어 모두 지웠습니다(팀 결정). 공원·숲 안의 나무는 녹지 면(OSM)을 나타내는 그림이라 남겼고, 한 그루씩의 자리는 실제가 아니라고 화면 '그림 읽는 법'에 밝혔습니다.
   - 같은 모양은 한 번에 그렸습니다(InstancedMesh).
     노트북·넓은 화면 모두 60fps이고, 첫 화면은 약 1초입니다(`tools/web_check.js`의 준비 시간 readyMs, 개발용 맥 기준 0.8~1.1초).
9. **자동 점검**
   - 화면을 고칠 때마다 playwright로 크롬을 띄워 폰(390×844)·노트북(1280×800)·넓은 화면(1680×1000)을 확인합니다(`tools/web_check.js`).
   - 보는 항목은 콘솔 오류, 패널 겹침·글자 잘림, 버튼 동작, 프레임 수(fps)입니다. 지금은 세 크기 모두 오류 0, 60fps입니다.
10. **함께 일한 방식**
    - 모든 변경은 브랜치를 만들어 PR로 합쳤습니다.
    - AI 코딩 도구 Claude Code 세션 여러 개가 역할을 나눴습니다: 근거 조사와 지도 바닥, 건물과 가상 손님, 화면·세운 것·문서.
      세션끼리 발견한 사실과 고치는 파일을 바로 알려 엇갈리지 않게 했습니다.
    - 사람이 정한 판단 기준(건물 전체 공실률, 동남권 1위 선택)과 허락이 필요한 일(상권 경계 따기)은 팀이 직접 결정했습니다.

## 함께 작업하는 규칙

- `main` 에 바로 올리지 않는다. `이름/작업` 브랜치(예: `junhyeok/vacancy-map`)에서 작업하고 PR로 합친다.
- API 키는 절대 커밋하지 않는다. `.env.example` 을 복사해 `.env` 로 만들어 쓴다(`.env` 는 `.gitignore` 에 있음).
- 근거 수치는 확인한 것·추정·미확인을 구분해 적는다. 가상 인물 결과를 실제 근거처럼 쓰지 않는다.
