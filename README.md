## 기술 스택

<!--
  각 항목에 "무엇을 · 왜 쓰는지"를 한 줄로 적는다. 실제로 쓰지 않게 되면 줄을 지운다.
  아래는 대구 드래프톤(dongseongno-3d)에서 실제로 쓴 구성을 기준으로 한 초안이다.

- **프론트엔드: HTML + JavaScript + three.js**
  <!-- 상권을 3D 미니어처로 보여 주는 웹 화면. 빌드 도구 없이 web/index.html 을 크롬으로 열면 바로 뜨게 한다(시연장에서 서버·설치 문제를 없애려고). -->
  - 상권 건물·도로·가게를 3D로 그리고, 그 위에서 가상 방문자가 움직이는 모습을 보여 준다.
  - 빌드 과정 없이 파일만 열면 실행된다.
- **백엔드: 없음(정적 파일) + Python 데이터 처리 스크립트**
  <!-- 서버를 두지 않는다. 공공데이터를 tools/ 의 Python 스크립트로 미리 가공해 web/ 에 JS·JSON으로 넣는다. -->
  - `tools/` 의 Python 3 스크립트가 공공데이터를 내려받고 걸러서 `data/processed/` 와 `web/` 에 넣는다.
  - 표준 라이브러리 위주로 쓰고, 실행은 `python3 -I tools/<스크립트>.py` 로 한다.
- **AI / 기타**
  <!-- AI를 어디에 왜 쓰는지는 심사 항목(AI 활용 적합성)과 바로 이어지므로, 'AI 없이 하면 어떻게 되는지'와 같이 적는다. -->
  - 가상 방문자(페르소나) 시뮬레이션: 도착 시각·예산·선호·대기 한계를 가진 가상 인물이 상권을 돌며 가게를 고른다.
  - **데이터 출처**
    - 한국부동산원 R-ONE 상업용부동산 임대동향조사: 상권별 공실률(중대형·소규모·집합·일반·1층)
    - 소상공인시장진흥공단 상가(상권)정보: 영업 중인 가게 위치·업종·층
    - 행정안전부 지방행정 인허가(일반·휴게음식점): 폐업 일자·좌표 → 빈 점포 후보 추정
    - 국토교통부 GIS건물통합정보 / OpenStreetMap: 건물 모양·층수, 도로
    - 카카오 로컬 API: 가게 검색·로드뷰 확인
  - 협업: GitHub(브랜치 + PR), Claude Code

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `data/raw/` | 내려받은 원자료 그대로(손대지 않음). 큰 파일은 올리지 말고 받는 방법을 `docs/data-sources.md` 에 적는다 |
| `data/processed/` | 스크립트로 가공한 결과 |
| `tools/` | 자료 받기·가공 스크립트 |
| `web/` | 시연 화면 |
| `docs/` | 조사 문서(근거·출처) |

## 함께 작업하는 규칙

- `main` 에 바로 올리지 않는다. `이름/작업` 브랜치(예: `junhyeok/vacancy-map`)에서 작업하고 PR로 합친다.
- API 키는 절대 커밋하지 않는다. `.env.example` 을 복사해 `.env` 로 만들어 쓴다(`.env` 는 `.gitignore` 에 있음).
- 근거 수치는 확인한 것·추정·미확인을 구분해 적는다. 가상 인물 결과를 실제 근거처럼 쓰지 않는다.
